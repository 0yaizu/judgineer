# samples

デモと評価用の題材。**運用で問題になりやすい書き方をわざと含めています。実運用では使わないでください。**

このフォルダ直下の説明は、検査対象のスナップショットに入らない（`a_company_api/` の中だけが AI に渡る）。
題材の中に「わざと」「サンプル」といった説明を書くと、AI がそれを根拠に問題を見送る判断をしてしまい、評価がゆがむため、注意書きはここに置く。

## a_company_api

デモ用: `TARGET_DIR=./samples/a_company_api bun run dev` で検査対象にできる（`TARGET_DIR` 未設定でもこれが選ばれる）。

含めている欠陥の正解表は `apps/backend/eval/golden.ts`。スキャナが拾う10件（`findings`）に加え、拾わないもの（`known_gaps`: DB 接続の閉じ忘れ・`date` 未指定・削除の空振り・キーの `==` 比較・脆弱性のある依存の版）も意図して残している。これらは AI の追加候補（引用が実在するものだけ採用）で検出する。依存の版だけは外部の脆弱性データが要るので、いまは検出しない。題材を変えたら、正解表と `apps/backend/test/sample.test.ts` も合わせる。
`bun run eval`（本物の `claude` を使う）で、AI の台本が正解表とどれだけ合うかを採点できる。
